# SFTP

## 使用流程

1. 在 Vaults 建立或選擇已保存的 SSH Host 與認證。
2. 點選 Vaults 右側固定的 SFTP 頁籤，選擇 Host 並建立連線。首次連線必須核對主機金鑰指紋；不自動信任或移除不相符金鑰。
3. 輸入遠端絕對路徑、點選資料夾、返回上一層或重新整理。列表包含名稱、類型、大小、修改時間及權限。
4. 使用上傳檔案／上傳資料夾，或將本機檔案與資料夾拖放至列表。選取多個遠端項目後按下載，再選擇本機目的資料夾。
5. 使用建立資料夾、重新命名或刪除；刪除需確認，非空資料夾不刪除。
6. 在 Transfer Queue 查看等候中、進行中、完成、失敗、位元組進度及平均速度。頁籤或 Host 切換不影響傳輸。已結束項目可手動清除。

## 架構

- `backend/sftp.Manager` 由 `app.NewApp` 組合，重用 `hostvault.ResolveRuntimeConfig` 與既有 SSH Connector；Password、私鑰、passphrase、憑證與 known_hosts 沿用原有處理，沒有新增 Credential 儲存或敏感資料日誌。
- 使用 `github.com/pkg/sftp v1.13.9`。SFTP 使用獨立 SSH 連線，避免終端關閉影響傳輸；不複製 SSH 認證或主機金鑰驗證實作。
- 每個連線有有界佇列與背景 worker，同一連線依序執行、多個連線可同時傳輸。遞迴資料夾作為一個佇列項目，統計所有檔案位元組。
- 前端只保存目前連線與路徑，掛載時讀取後端連線及傳輸快照，顯示期間每 750 ms 更新。卸載只解除輪詢與拖放監聽。
- 所有傳輸採固定緩衝區串流；本機檔案透過 `os.Root` 限制在所選目錄內。目的檔案使用 exclusive create，不覆寫；符號連結與特殊檔案拒絕傳輸。
- 應用程式結束／更新時沿用既有操作凍結及確認流程，納入未完成 SFTP 傳輸；確認後關閉連線，排隊與執行中工作標記失敗。
- 固定頁籤直接排列為 Vaults → SFTP → Kubernetes（若開啟）→ Terminal，SFTP 不參與終端拖曳、合併與關閉流程。

## 邊界與限制

- 佇列只在本次應用程式執行期間保留；不提供暫停、續傳、自動重試或跨重啟恢復。
- 每個連線最多 256 個尚未完成的頂層項目，單一資料夾最多掃描 100000 個項目。同一連線序列傳輸。
- 不覆寫同名檔案、不合併既有資料夾；有同名目的項目時回報失敗。資料夾掃描發現符號連結時整個項目失敗。
- 刪除僅處理一般項目、連結與空目錄，不遞迴刪除非空資料夾。
- 失敗會嘗試移除本次未完成檔案；已完成的子檔案／資料夾保留。遠端斷線後無法保證清除遠端半成品，重試前需檢查目的目錄。
- 下載使用限制性的本機權限，不保留原始 owner、權限、修改時間或 ACL；列表仍顯示遠端資訊。
- 進度總量根據傳輸前掃描；來源在傳輸中變更時不提供一致性快照。速度為工作開始後的平均值。
- 原生檔案選擇與拖放需要 Wails 桌面執行環境，純瀏覽器預覽不會連線到使用者 Host。

## 驗證

- Go 整合測試啟動僅限 loopback 的 SSH/SFTP 伺服器，驗證保存認證解析、主機金鑰拒絕、多項目遞迴往返、空檔案、目錄資訊、建立／重新命名／刪除、同名保護、符號連結拒絕、關閉保護及串流錯誤。
- 前端測試驗證固定頁籤順序、不可拖曳、路徑處理、HTML 跳脫、卸載生命週期與原生拖放介面。
- 原生選檔、Finder 拖放、正式 Host 及 Windows／Linux 桌面互動仍需在相應環境手動驗收。

## 本機雙欄與連線搜尋

- SFTP 頁籤附有檔案傳輸圖示。左側為本機檔案，右側為遠端檔案；本機預設開啟家目錄，支援輸入絕對路徑、上一層、重新整理及原生資料夾選擇。
- 勾選本機檔案或資料夾後，可拖曳至遠端資料夾列，上傳到該子目錄；拖到列表空白處或一般檔案列，上傳到目前遠端路徑。拖曳期間顯示目的路徑並標示資料夾，也支援「上傳選取項目」。
- 本機路徑與父目錄由 Go 依作業系統產生，避免 Windows 路徑在前端誤用 POSIX 分隔符號。只讀取檔案中繼資料，傳輸仍走原有背景佇列。
- 搜尋欄可依 Alias、IP／hostname 或名稱篩選，忽略大小寫及首尾空白，沒有符合項目時不可建立連線。
- 最近成功建立 SFTP 連線的 Host 排在前面；最近紀錄僅在既有前端本機儲存中保存 Host ID 與時間，最多 100 筆，重啟後可沿用。不保存另一份認證或 IP。失敗的連線不更新最近排序。
- 搜尋不會中斷目前連線；遠端欄標題持續顯示實際連線目標，避免與搜尋中的其他 Host 混淆。

## 傳輸狀態與平均速度修正

- 完成／失敗後保留實際傳輸位元組除以工作耗時的平均速度，不再清零；尚未傳輸資料或空檔案顯示「—」。
- 「連線已切換或操作尚未完成」表示此次拖曳未加入佇列，不代表既有工作失敗。提示現在明確區分「此次未開始上傳」與先前完成紀錄。
- 上傳後的背景目錄更新不再取得操作忙碌鎖，不會短暫阻擋下一次拖曳。過期回應不覆蓋新路徑，拖曳期間不重建目錄列表。
- 完成前核對掃描大小、實際傳輸位元組與目的檔案大小，保留寫入／關閉／驗證錯誤；檔案大小驗證不等同內容雜湊或持久化儲存保證。
- 進行中傳輸最多顯示 99%，只有後端成功確認後才顯示完成。失敗即使已送出全部位元組，仍以紅色失敗狀態及「未完成」顯示。
- 修正不會回補本次執行中已被清零的舊紀錄，需啟動新建置後以新傳輸驗證。
